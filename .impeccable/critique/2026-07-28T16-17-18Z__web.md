## New Finding (Found and Fixed Within This Pass)

**Clear filters didn't reset the Area/Sort `<select>` DOM state.** The design-review pass caught this live: after picking an area and clicking Clear filters, the URL and result count correctly reset to all 731 leads, but the Area dropdown kept showing the previously-picked area — a genuine "your own reset didn't work" contradiction. Root cause: those two selects used React's uncontrolled `defaultValue`, which only applies at mount. Fixed immediately (commit `b89b85a`): converted both to controlled inputs matching the search/min-discount fields' pattern, and the clear handler now resets all four fields' visible state. Re-verified live: select an area → Clear filters → select value now correctly empties.
